# 运行副本启动修复与测试关联清理

目标：0.1.5-rc.2 副本，profile `web`。用户要求恢复启动、清理现有测试关联，并核查 Maintenance 扩展看板。

## 根因与修复

贴纸候选安装把包来源路径改为 candidate2 后，profile 配置指纹改变，但上次部署未重新执行 Maintenance 接入验证。Launcher 在 prepare 阶段被有效的旧绑定校验拦截。对 19 个已安装包及全部运行证明文件重新校验后，通过 Engine 正式的 integration connect 接口更新绑定。

官方 plugin install 还把套件已有的 `dsh-annotation-core` 和 `dsh-session-sticker-board` 自动加入顶层 bundles，改变套件装载关系。恢复安装前的顶层 bundles 后，保留它们在引用套件内的配置。再次验证绑定后启动成功，浏览器恢复贴纸样式与“会话贴纸”入口。

部署脚本已补上安装后恢复原 bundles 的步骤。包更换后的验收必须同时检查安装身份、组合关系、Maintenance 绑定及真实启动，不能只验证文件哈希。

## 清理范围

- 使用 Core 的删除入口清除当前待发送测试引用。
- 使用 Companion 的 link-delete 接口解除 1 条 Obsidian 关联，移除对应的笔记会话链接块。
- 使用 Maintenance 知识写入接口删除该关联对象及对应的 1 张会话贴纸。
- 已删除状态保留在扩展历史中，防止旧端再次同步恢复；当前对象列表为空。
- 未删除笔记正文、会话正文或用户后来建立的新会话；未调用模型。

## 验证结果

`artifacts/linked-notes-20260914/repair-cleanup-validation.json` 记录：副本运行中，接入状态 connected；当前运行失败事件 0；有效关联、会话贴纸、注释和 Companion 待发送引用均为 0；主实例配置未变。清理前后原生会话真源摘要一致。

实际浏览器确认会话页“会话贴纸”入口恢复，打开后显示“还没有会话贴纸”。Maintenance “扩展数据”下的“跨会话上游引用”“知识链接”“会话贴纸”和“ThoughtDAG”均 ready。对象总数包含已删除历史；ThoughtDAG 当前没有已保存画布对象。

ThoughtDAG 适配面板支持对象目录、节点/连线预览、版本、关联会话、冲突与删除恢复。完整画布交互由 ThoughtDAG 插件提供；“适配器详情”设置页用于诊断引擎版本适配，不是插件对象目录。

本轮按用户要求清空关联，没有重新创建测试关联或发送模型消息；新的“关联笔记→引用到本轮”路径由自动化测试覆盖，未在清理后制造新的实用户引用进行发送验收。
