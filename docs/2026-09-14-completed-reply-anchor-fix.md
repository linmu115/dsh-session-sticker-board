# 会话贴纸的完整回复定位修复

## 原因

RC2 的 assistant-step 会话行使用展示节点身份（例如 `14:assistant-step21:1`），而 Maintenance 图谱预览要求 assistant/message 的真实 message ID。此前复用了旧贴纸的展示锚点，导致正常完成的回复返回“没有可读取的完整回复，或所选回复已不可用”。

独立会话贴纸现在读取官方 AssistantChatData.finalNode.messageId，仅接受 settled 回复。旧注释贴纸的布局锚点及反向定位保持原语义。缺失最终消息或流式、截断回复会在选区入口提示等待，不猜测最近一条回复。

来源解析和固定版本预览先于新建目标会话执行。预检失败保留选区和工作区，不产生空会话；成功后依旧固定到所选完整回复，不包含之后的轮次，不自动发起模型回答。

## 验证

- 类型检查和完整 116 项测试通过。
- 覆盖真实消息 ID 与展示锚点分离、反向查找、未完成和无最终消息拒绝，以及来源失败时不创建会话。
- 对运行副本中同一来源版本执行只读验证：页面编号返回 409 和原错误，真实 message ID 返回 200 及问答上下文。未创建会话、未触发模型调用。
